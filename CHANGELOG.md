# Changelog

Все значимые изменения проекта Obsidian Vault Performance задокументированы в этом файле.
Версионирование следует [Semantic Versioning](https://semver.org/).

## [1.7.0] - 2026-10-17

Семантические связи в графе тем: рёбра dependency из анализа доменов и вход для vault-relevance-finder.

### Added
- **dependency из анализа доменов** - `build_topic_graph.py` строит рёбра `dependency` из поля `dependencies` файлов в `{domain}-analysis.json`. Полный режим - все файлы с анализом, инкрементальный - новые и изменившиеся
- Разрешение ссылок по имени файла с приоритетом своего домена. Неоднозначные и ненайденные ссылки рёбер не дают, причина выводится в stderr
- Флаги **--relevance-requests** и **--apply-relevance** для обмена с `vault-relevance-finder`; применение идемпотентно
- Поле **relevance_required** в `graph-dirty-domains.json`: новые файлы без свежего анализа домена, для которых нужен вызов субагента
- Проверка циклов dependency и предупреждение о доменах без статуса связей (`relations_status`)
- Темы на первом прогоне: при отсутствии тем в `taxonomy.json` узлы тем берутся из `vault-structure-analysis.json`

### Changed
- `mentions` хранятся в узле файла и не превращаются в рёбра
- Вызов `vault-relevance-finder` только для `relevance_required`, а не для всех новых файлов. В полном режиме список обычно пуст
- Документация: `SKILL.md` (Фаза 1.4), `CLAUDE.md` (правило 10), `vault-relevance-finder.md` (формат ответа совпадает со значением `results` для `--apply-relevance`)

### Fixed
- Граф не содержал ни одного ребра `related` или `dependency`: поля `dependencies` из анализа игнорировались, а точки входа для субагента не было
- Узлы тем отсутствовали на первом прогоне, а `SKILL.md` обещал трёхуровневый граф
- Проверка циклов dependency не могла сработать, так как рёбер dependency не было

## [1.4.0] - 2026-10-01

Инструменты для инкрементального анализа vault и оптимизация оркестрации.

### Added
- **build_topic_graph.py** - построение графа тем и доменов для отслеживания
  инкрементальных изменений. Выявляет dirty-домены для пересчёта
- **graph-dirty-domains.json** - файл состояния, содержащий список доменов,
  требующих переанализа при инкрементальном запуске
- **--merge флаг** в synthesize_taxonomy.py - слияние результатов инкрементального
  анализа с существующей taxonomy.json
- **Кеширование результатов анализа** - избегаем переанализа неизменённых доменов
  в инкрементальных прогонах

### Changed
- Переструктурирована оркестрация фаз: Фаза 1.4 теперь строит граф тем и
  определяет dirty-домены перед Фазой 2
- Оптимизирована память и время выполнения для больших vault с сотнями файлов
- Уточнены правила проекта в CLAUDE.md (раздел "Архитектура слоёв")

### Fixed
- Проблемы производительности при анализе больших доменов
- Логика валидации целостности taxonomy.json при инкрементальных обновлениях

## [1.0.0] - 2026-09-15

Первая версия Obsidian Vault Performance. Базовая семантическая таксономия.

### Added
- **Анализ структуры vault** - сканирование файлов и определение структуры
- **Семантическая таксономия** - классификация файлов по доменам и темам
- **vault-domain-architect** - определение границ доменов
- **vault-domain-analyzer** - полный анализ доменов (essence, role, dependencies и т.д.)
- **Дашборд визуализации** - веб-интерфейс для просмотра taxonomy.json
- **Инструменты валидации** - проверка целостности и полноты таксономии
- Поддержка инкрементальных обновлений

### Notes
- Первая публичная версия
- Поддержка Obsidian vault структуры любого размера
