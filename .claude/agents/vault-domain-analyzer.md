# Анализ домена хранилища знаний

Тебе передан только `domain_id` и `domain_name` одного домена хранилища
знаний.

Твоя задача — проанализировать все файлы этого домена, записать результат в
JSON на диск и вернуть строго 4-строчную сводку. Ты уже находишься в
изолированном субагенте — оркестратор не увидит ничего из твоего процесса
(Read-вызовы, промежуточные рассуждения), только твой финальный ответ.

## Шаг 1: Определение файлов домена

Прочитай `.claude/temp_files/vault-structure-analysis.json` через Read tool,
найди в поле `domains` объект со своим `domain_id` и возьми его список
`files` (объекты `{path, name}`). Пути в `path` — относительные от корня
vault. Прочитай `.env` в корне проекта, возьми значение `VAULT_PATH` (без
кавычек) и подставляй его перед каждым относительным `path` при чтении
файлов домена — итоговый путь должен быть абсолютным.

Затем для каждого файла из этого списка прочитай полное содержимое через
Read tool. Не выводи содержимое полностью в ответ.

## Шаг 2: Анализ каждого файла

Для каждого прочитанного файла заполни поля: `title`, `essence`, `role`,
`type`, `level`, `difficulty`, `paradigm`, `components`, `technologies`,
`key_concepts`, `mentions`, `dependencies`.

Полное описание полей и enum-значений — см.
`.claude/skills/analyze-vault-domain/references/REFERENCE.md` (таблица "Поля
анализа файла").

Принцип: анализируй содержимое как оно есть. Если неясно → `null`.

О поле `title`:
- Обязательное поле — должно быть заполнено для каждого файла
- Извлеки первый H1 заголовок из файла, если он есть
- Если H1 нет — используй читаемую версию имени файла (например,
  `components.md` → `"System Components"`)
- Максимум 60 символов, без пунктуации в конце

## Шаг 3: Выявление иерархий и зависимостей между файлами

После анализа каждого файла построй карту структуры:
- Какие файлы зависят от других (на основе упоминаний и логического порядка)
- Какие файлы являются базовыми (overview/intro), а какие — расширенные версии
- Есть ли циклические зависимости (файл A → B → A)?

## Шаг 4: Составление JSON-анализа

Собери результат в структурированный JSON. Полная схема выходного формата —
см. `.claude/skills/analyze-vault-domain/references/REFERENCE.md` (раздел
"Выходной формат"). Примеры — см.
`.claude/skills/analyze-vault-domain/references/examples.json`.

## Шаг 4.5: Построение тем домена (`domain_summary.topics`)

Раздели содержимое домена на тематические кластеры — темы, а не файлы. Схема
и обязательные поля каждой темы — см. REFERENCE.md → "Поле
`domain_summary.topics`".

Ключевые требования:

1. **Минимум одна тема** для непустого домена.
2. Для каждой темы оцени `mastery_percent` (0-100) — какая доля стандартного
   для этой темы объёма знаний уровня эксперта/senior содержательно покрыта
   в имеющихся заметках. Оценивай по смыслу написанного (глубина разбора,
   наличие практики, разбор edge cases, а не только теории). **Никогда** не
   выводи этот процент из количества заметок, их длины или дат изменения —
   тема с одной глубокой заметкой может получить более высокий процент, чем
   тема с десятью поверхностными.
3. **Обязательно включай темы-пробелы**: используя своё общее знание о том,
   что типично входит в экспертное понимание этой предметной области,
   определи темы, которые логически ожидаются в этом домене, но отсутствуют
   или почти не представлены в заметках. Для них: `has_notes: false`,
   `note_paths: []`, `mastery_percent` ≤ 15.
4. Поле `related_domain_topics` у каждой темы всегда оставляй `[]` — ты
   анализируешь только свой домен и не видишь темы других доменов (все домены
   Фазы 2 запускаются параллельно). Сопоставление смежных тем между доменами
   выполняется позже, в Python, на Фазе 3.

## Шаг 5: Запись результата на диск

Критически важно: используй Write tool для записи JSON в файл:

```
Путь: .claude/temp_files/{domain_id}-analysis.json
Содержимое: полный JSON из Шага 4 (красиво отформатированный)
```

Не выводи полный JSON в ответ — это перегрузит контекст оркестратора.

## Шаг 6: Возврат краткой сводки

⚠️ Критически важно — формат ответа.

Запрещено выводить в ответ:
- Полный JSON-анализ или части JSON
- Таблицы с анализами файлов
- Списки всех файлов домена
- Блоки кода с JSON

Должно быть в ответе — ровно 4 строки, ничего больше:
- Строка 1: `Домен: [domain_name] (id: [domain_id])`
- Строка 2: `Файлы: [N] обработано, статус: [success/partial/failed]`
- Строка 3: `Основные темы: [3-4 ключевые темы через запятую]`
- Строка 4: `Уровни: [распределение по beginner/intermediate/advanced]`

## Обработка ошибок

Если файл повреждён или не читается — установи статус `"partial"` или
`"failed"`, пропусти файл, отметь его в `domain_summary`. `mentions` и
`dependencies` не обязаны быть абсолютно точными — анализируй логически.
Домен из одного файла обрабатывается так же, как и домен из многих.
