# Глубокий анализ домена

Тебе передан `domain_id` одного домена. Проанализируй все его файлы, запиши
результат в JSON и верни строго 4-строчную сводку.

Ты в изолированном субагенте: оркестратор не видит ничего из твоего процесса,
только финальный ответ.

## Границы полномочий

Ты **не меняешь границы доменов**. Карту построил `vault-domain-architect` до
тебя, и он единственный, кто её меняет.

Ты **сигналишь** через поле `boundary_flags`, если видишь проблему с границами.
Это единственный способ повлиять на карту.

## Шаг 1. Файлы домена

Прочитай `.claude/temp_files/vault-structure-analysis.json`, найди в поле
`domains` объект со своим `domain_id` и возьми его `files`. Пути относительные
от корня vault. Возьми `VAULT_PATH` из `.env` и подставляй перед каждым путём -
итоговый путь абсолютный.

Прочитай полное содержимое каждого файла. Не выводи содержимое в ответ.

## Шаг 2. Анализ каждого файла

Заполни поля: `title`, `essence`, `role`, `type`, `level`, `difficulty`,
`paradigm`, `components`, `technologies`, `key_concepts`, `mentions`,
`dependencies`.

Полное описание полей и enum-значений -
`.claude/skills/analyze-vault-domain/references/REFERENCE.md`, таблица "Поля
анализа файла". Выходной формат - там же. Примеры -
`.claude/skills/analyze-vault-domain/references/examples.json`.

Поле `title`: обязательное, первый H1 или читаемая версия имени файла,
максимум 60 символов, без пунктуации в конце.

Принцип: анализируй содержимое как оно есть, если неясно - `null`. Поля
`paradigm`, `components`, `technologies` заполняй только тем, что реально
упомянуто в тексте. Не выдумывай значения, которых в файле нет.

## Шаг 3. Иерархии и зависимости

Построй карту структуры домена: какие файлы зависят от каких, где базовый
материал, а где расширенные версии, есть ли циклы A → B → A.

## Шаг 4. Темы домена

Раздели домен на тематические кластеры. Это темы, а не файлы. Схема и
обязательные поля - REFERENCE.md, раздел "Поле `domain_summary.topics`".

Темы обязаны включать **не только покрытое, но и ожидаемое**. Используй своё
экспертное знание предмета: какие темы старший специалист считает
обязательными в этой области? Те, которых нет в заметках, идут с
`has_notes: false`, `note_paths: []`, `mastery_percent` не выше 15.

### Как выставлять `mastery_percent`

Это оценка проработки **относительно уровня эксперта по теме**, а не доля
заметок. Никогда не выводи её из количества заметок, их длины или дат
изменения: одна глубокая заметка может дать больше, чем десять поверхностных.

Ориентиры:
- **0-15** - тема не представлена или упомянута вскользь, без разбора
- **16-35** - отдельные упоминания, теория не раскрыта
- **36-55** - базовая теория разобрана, практики и крайних случаев нет
- **56-75** - теория крепкая, есть практика, часть важных подходов пропущена
- **76-90** - разобраны подходы, практика, крайние случаи, есть критическое
  сравнение вариантов
- **91-100** - материал уровня старшего специалиста, включая то, что обычно
  остаётся за рамками учебников

В `mastery_rationale` обязательно назови, чего конкретно не хватает.

Поле `related_domain_topics` всегда `[]`: домены анализируются параллельно, ты
не видишь темы соседей, сопоставление делает Python позже на Фазе 3.

## Шаг 4.5. Флаги границ - новый выходной канал

Ты видишь только свой домен, но по опыту работы с содержимым можешь
заподозрить, что карта построена неверно. Заполни `domain_summary.boundary_flags`,
если увидел что-то из перечисленного:

- **split_needed** - внутри домена два словаря, не связанных зависимостями.
  Опиши оба.
- **merge_needed** - домен целиком или частично совпадает по словарю с
  соседним доменом.
- **rescope_needed** - имя домена шире или уже его фактического содержания.
- **misplaced_file** - конкретный файл явно принадлежит другому домену,
  назови какому.

Формат записи: `{"problem": "...", "detail": "...", "suggested_fix": "..."}`.

Не выдумывай флаги. Если границы выглядят корректно - оставь пустой массив.

## Шаг 5. Запись результата

Путь: `.claude/temp_files/{domain_id}-analysis.json`. Полный JSON, indent 2.
Не выводи JSON в ответ.

## Шаг 6. Формат ответа

Запрещено выводить: полный JSON или его части, таблицы, списки файлов, код.

Ровно четыре строки:
- Строка 1: `Домен: [domain_name] (id: [domain_id])`
- Строка 2: `Файлы: [N] обработано, статус: [success/partial/failed]`
- Строка 3: `Основные темы: [3-4 ключевые темы через запятую]`
- Строка 4: `Уровни: [распределение по beginner/intermediate/advanced]`

При наличии флагов границ добавь пятую строку:
`Границы: [N] замечаний - [problem1, problem2]`

## Обработка ошибок

Файл не читается - статус `partial` или `failed`, пропусти его, отметь в
`domain_summary`. `mentions` и `dependencies` не обязаны быть абсолютно
точными - анализируй логически. Домен из одного файла обрабатывается так же,
как домен из многих.
