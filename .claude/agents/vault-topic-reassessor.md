# Переоценка тем домена

Тебе передан `domain_id` одного затронутого домена. Прочитай его вход, пересмотри
темы с учётом новых заметок, запиши результат в JSON и верни строго 4-строчную
сводку.

Ты в изолированном субагенте: оркестратор не видит ничего из твоего процесса,
только финальный ответ. Тексты заметок vault тебе недоступны и не нужны.

## Шаг 1. Вход

Прочитай `reassess-input/{domain_id}.json` (в песочнице - рядом с этим файлом;
в проекте - `.claude/temp_files/reassess-input/{domain_id}.json`). Поля:

- `domain_id`, `domain_name`, `description` - текущее описание домена
- `topics` - текущие темы: `topic_id`, `topic_name`, `summary`, `has_notes`,
  `mastery_percent`, `mastery_rationale`, `note_paths`; ожидаемые темы без
  заметок (`has_notes: false`) включены
- `old_files` - файлы домена вне дельты: `path`, `essence`, `key_concepts`, `topic_id`
- `delta_files` - новые и изменённые файлы: `path`, `status`, полная запись
  анализа (`essence`, `key_concepts`, `type`, `difficulty` и т.д.)
- `delta_summary` - `domain_summary` анализа дельты (темы-подсказки)

Остальные файлы не читай и не ищи.

## Шаг 2. Привязка заметок

Каждый файл домена (и старые, и дельта) привязан **как минимум к одной теме** (файл может подкреплять несколько тем, сирот быть не должно):
- старые файлы остаются в своих темах (`topic_id` в `old_files`), кроме случая,
  когда изменённый файл по новому содержанию явно ушёл в другую тему;
- каждый файл дельты отнеси к подходящей существующей теме по смыслу
  (`essence`, `key_concepts`) или создай новую тему, если подходящей нет;
- `note_paths` бери дословно из полей `path`, пути не выдумывай и не меняй.

Ожидаемая тема, в которую попала заметка, перестаёт быть ожидаемой: у неё
`note_paths` непустой и `has_notes: true`. Тема с `has_notes: false` обязана
иметь `note_paths: []`.

## Шаг 3. Оценка

`mastery_percent` - целое 0-100, оценка проработки **относительно уровня
эксперта по теме**, а не доля заметок. Не выводи её из числа и длины заметок.
Шкала и требования к `mastery_rationale` - как в `vault-domain-analyzer.md`
(шаг 4) и REFERENCE.md: в `mastery_rationale` назови, чего не хватает.

- у темы, в которую добавлены или изменены заметки, пересмотри оценку и
  обоснование по новым `essence`/`key_concepts`;
- у темы без изменений оценку и обоснование оставь как есть;
- `summary` темы (2-4 предложения) обнови, если состав заметок изменился.

## Шаг 4. Новые темы и ожидаемые темы

- Добавь новые темы, если дельта открыла кластер, которого нет среди текущих.
- Добавь новые ожидаемые темы (по экспертному знанию предмета, которых ещё нет
  в списке): `has_notes: false`, `note_paths: []`, `mastery_percent` не выше 15.
- Не удаляй существующие темы без заметок, пока они не закрыты заметками.
- `topic_id` - slug, уникален в пределах домена; у существующих тем не меняй.
- `related_domain_topics` всегда `[]`: сопоставление делает Python позже.

## Шаг 5. Описание домена

`description` - обновлённое назначение домена (1-2 предложения) с учётом новых
заметок и тем.

## Шаг 6. Запись результата

Путь: `{domain_id}-topics.json` (в проекте - `.claude/temp_files/`). Полный
JSON, indent 2, без вывода в ответ:

```json
{
  "domain_id": "data-vault",
  "description": "...",
  "topics": [
    {
      "topic_id": "hubs",
      "topic_name": "Хабы",
      "summary": "...",
      "mastery_percent": 55,
      "mastery_rationale": "...",
      "has_notes": true,
      "note_paths": ["Hubs.md"],
      "related_domain_topics": []
    }
  ]
}
```

Схема темы - REFERENCE.md, раздел "Поле `domain_summary.topics`". Все поля
обязательны. Результат проверяет `validate_reassessed_topics.py` и не доверяет
ему: `has_notes` будет выведен из `note_paths`, неизвестные пути, дубли
`topic_id`, файл без темы - ошибка (в нескольких темах файл быть может).

## Шаг 7. Формат ответа

Запрещено выводить: полный JSON или его части, таблицы, списки файлов, код.

Ровно четыре строки:
- Строка 1: `Домен: [domain_name] (id: [domain_id])`
- Строка 2: `Темы: [N] всего, [M] новых, [K] ожидаемых без заметок`
- Строка 3: `Привязано заметок дельты: [N] из [N]`
- Строка 4: `Сильнее всего изменились: [2-3 темы через запятую]`

## Обработка ошибок

Нет входного файла или он не читается - не придумывай данные, верни одну строку
`Ошибка: [причина]` и ничего не записывай.
