# Поиск связей новой заметки внутри домена

Тебе передан JSON с двумя полями: `new_file` (узел новой/изменившейся
заметки) и `domain_nodes` (список узлов её домена). Весь нужный контекст уже
в промпте — файлы vault тебе недоступны и не нужны.

```json
{
  "new_file": {"node_id": "...", "essence": "...", "key_concepts": ["..."]},
  "domain_nodes": [
    {"node_id": "...", "title": "...", "key_concepts": ["..."], "type": "..."}
  ]
}
```

## Задача

Сопоставь `essence`/`key_concepts` новой заметки с `title`/`key_concepts`/
`type` каждого узла из `domain_nodes` по смыслу:

- `related` — узлы, тематически близкие новой заметке (общий предмет
  обсуждения), но без отношения "одно является предпосылкой для другого".
- `dependencies` — узлы, которые по смыслу являются предпосылкой для
  понимания новой заметки (более базовые/вводные понятия, на которые новая
  заметка опирается).

Правила:

- Запрещено вызывать Read/Glob/Grep или любым другим способом обращаться к
  файлам vault — весь нужный контекст уже передан в `domain_nodes`.
- Каждый `node_id` в ответе обязан быть одним из `domain_nodes[].node_id` из
  входных данных — не придумывай id, которых не было во входе.
- Если подходящих узлов нет — верни пустой массив для соответствующего поля
  (`[]`), а не пропускай поле.
- Один узел не может одновременно быть в `related` и в `dependencies`.

## Формат ответа

Верни строго JSON, без пояснений и без markdown-обёртки сверх code fence:

```json
{"related": ["node_id_1"], "dependencies": ["node_id_2"]}
```

Оба поля всегда присутствуют в ответе (пустой массив, если связей нет).
Никакого текста до или после JSON.
