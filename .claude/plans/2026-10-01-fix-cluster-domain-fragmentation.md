# Фикс: новые файлы распадаются на отдельные домены вместо слияния с существующим

## Проблема (воспроизведено на реальном прогоне инкремента 2026-10-01)

6 новых файлов из `Оптимизация запросов PostgreSQL/QPT/` должны были влиться
в уже существующий домен `оптимизация-запросов-postgresql` (4 файла), но
`cluster_from_topics.py` создал для них 6 новых доменов `postgresql-2..7`.

## Причины (найдены, подтверждены экспериментом)

1. `build_clusters()` группирует файлы строго по точному совпадению строки
   `primary_topic` (`topic_groups[analysis["primary_topic"].lower()]`). Каждый
   новый файл получил от `vault-topic-classifier` свою уникальную формулировку
   темы (агент не видит темы уже существующих файлов того же домена/папки) -
   поэтому 6 файлов = 6 разных групп = 6 кластеров, и фоллбэк по
   `secondary_topics` (строки 247-283) никогда не срабатывает, т.к. все
   кластеры уже "заняты" после первого прохода (confidence 0.9-0.95 > порога).
2. `normalize_cluster_id()` вырезает regex'ом всё, кроме `[a-z0-9]` - это
   стирает кириллицу. Все 7 вариантов темы ("Обработка запросов PostgreSQL",
   "Доступ к данным в PostgreSQL" и т.д.) после нормализации схлопываются в
   один и тот же слаг `"postgresql"`, отсюда и совпадающая нумерация
   `postgresql-2..7` - баг маскирует проблему, но сам по себе не является её
   причиной (сортировка по кластерам происходит раньше, по точной строке).

## Фикс

1. `normalize_cluster_id()` - сохранять unicode-буквы (кириллицу), а не только
   ASCII, чтобы cluster_id был осмысленным и не схлопывался в один слаг для
   разных тем.
2. Новый шаг после `build_clusters()` - `reconcile_with_existing_domains()`:
   если текущий `.claude/temp_files/taxonomy.json` существует, построить карту
   "топ-level папка vault → domain_id/domain_name" по уже существующим доменам
   (только для папок, однозначно принадлежащих одному домену). Для каждого
   нового кластера, все файлы которого лежат в папке, уже закреплённой за
   существующим доменом, переподключить кластер к этому domain_id/name вместо
   создания нового. Кластеры с одинаковым итоговым cluster_id после этого шага
   объединяются в один (files суммируются, metadata пересчитывается).
3. Точечно исправить уже испорченные данные (слить `postgresql-2..7` обратно в
   `оптимизация-запросов-postgresql` в `taxonomy.json` и `topic-graph.json`) -
   без повторного вызова `vault-domain-analyzer` (данные уже есть, это чисто
   объединение JSON, не анализ содержимого).

## Итог

Реализовано полностью. Причина была в двух местах:
`cluster_from_topics.py` группировал файлы строго по точной строке
`primary_topic` без учёта уже существующих доменов, а баг в
`normalize_cluster_id` (ASCII-only regex) маскировал последствия, схлопывая
разные темы в один слаг `postgresql`. Добавлен дешёвый post-hoc шаг сверки
новых кластеров с существующими доменами по топ-level папке vault (без
дополнительных вызовов LLM-агентов). Существующие испорченные данные
(`taxonomy.json`, `topic-graph.json`) исправлены точечным слиянием JSON, без
повторного запуска `vault-domain-analyzer`.

Осталось за рамками этого фикса (не блокирует, отдельная проблема): первый
запуск `build_topic_graph.py` в режиме `--new-only`/incremental построил
граф только из новых файлов текущего прогона - остальные ~68 существующих
файлов vault в `topic-graph.json` не попали. Нужен отдельный `--full` прогон
`build_topic_graph.py`, когда это понадобится для работы с графом тем.
