# Справочник: analyze-vault-domain

Компактный справочник с примерами и best practices. Для полного описания процесса см. SKILL.md.

---

## Входные данные

```json
{
  "domain_id": "architecture",
  "domain_name": "System Architecture",
  "domain_files": [
    { "path": "docs/architecture/overview.md", "name": "overview" },
    { "path": "docs/architecture/components.md", "name": "components" }
  ]
}
```

---

## Поля анализа файла

| Поле | Пример | Примечание |
|------|--------|-----------|
| `title` | `"Star Schema"` | **Обязательное**. Человекочитаемый заголовок (H1 или имя файла в читаемом виде) |
| `essence` | `"Описывает основные компоненты"` | 1-2 предложения, краткая суть файла |
| `role` | `"Базовый материал для новичков"` | Место в иерархии, назначение |
| `type` | `"overview"`, `"reference"`, `"pattern"` | Категория контента (см. "Типы контента") |
| `difficulty` | `"beginner"`, `"intermediate"`, `"advanced"` | Уровень для читателей |
| `level` | `"overview"` / `"deep-dive"` / `"reference"` | Детализация материала |
| `paradigm` | напр. название методологии/подхода, если файл явно её описывает или следует ей | Извлекай из содержимого, если домен оперирует именованными методологиями/парадигмами. Если не применимо → `null` |
| `components` | напр. названия технических строительных блоков/сущностей, о которых говорит файл | Извлекай из содержимого домена (структуры, модули, элементы архитектуры — что уместно для данного типа знаний) |
| `technologies` | напр. названия конкретных инструментов/языков/продуктов, упомянутых в файле | Извлекай из содержимого, если файл называет конкретные технологии |
| `key_concepts` | `["компонент", "интерфейс", "DI"]` | 5-15 главных идей, ключевые термины |
| `mentions` | `["patterns.md"]` | Упоминания других файлов (найти по содержимому) |
| `dependencies` | `["overview.md"]` | Логические зависимости (файлы, которые надо прочитать перед этим) |

**Про `paradigm`, `components`, `technologies`**: это результат анализа текста, а не готовые теги — в исходных файлах явной разметки может не быть. Извлекай только то, что реально упомянуто в содержимом; если домен/файл не оперирует такими сущностями — оставляй `null` / `[]`, не придумывай значения.

**Принцип**: если неясно → `null`.

## Выходной формат

```json
{
  "domain_id": "architecture",
  "domain_name": "System Architecture",
  "analysis_date": "2026-08-02",
  "total_files": 2,
  "analysis_status": "success",
  "files": [ { ...файл 1... }, { ...файл 2... } ],
  "domain_summary": {
    "key_themes": ["многослойность", "компоненты"],
    "main_concepts": [...],
    "content_distribution": { "by_type": {...}, "by_difficulty": {...} },
    "dependencies_overview": "overview → [components, patterns]",
    "topics": [
      {
        "topic_id": "async-programming",
        "topic_name": "Асинхронное программирование",
        "summary": "Покрыты корутины и event loop, есть практика с race conditions.",
        "mastery_percent": 72,
        "mastery_rationale": "Заметки разбирают реальные баги конкурентности, что типично для senior-уровня, но нет материала про structured concurrency.",
        "has_notes": true,
        "note_paths": ["docs/architecture/async.md"],
        "related_domain_topics": []
      },
      {
        "topic_id": "distributed-transactions",
        "topic_name": "Распределённые транзакции",
        "summary": "Тема почти не представлена — упомянута вскользь в одном файле без разбора паттернов.",
        "mastery_percent": 4,
        "mastery_rationale": "Нет ни одной заметки, разбирающей saga/2PC или компенсирующие транзакции — стандартный для этой темы материал senior-уровня отсутствует.",
        "has_notes": false,
        "note_paths": [],
        "related_domain_topics": ["api-design:idempotency-keys"]
      }
    ]
  }
}
```

### Поле `domain_summary.topics`

Новый уровень между доменом и файлом — тематический кластер, а не файл. Обязателен для непустого домена (минимум одна тема).

| Поле | Тип | Обязательность | Примечание |
|---|---|---|---|
| `topic_id` | string | обязательно | slug, уникален в пределах домена |
| `topic_name` | string | обязательно | человекочитаемое название |
| `summary` | string | обязательно | 2-4 предложения — что покрыто, а что нет |
| `mastery_percent` | integer 0-100 | обязательно | оценка проработки **относительно уровня эксперта/senior по теме**, формируется содержательным анализом. Запрещено выводить это число из количества/длины заметок, дат изменения или иных метаданных — только из смысла того, что написано, в сравнении со стандартным для темы объёмом экспертных знаний |
| `mastery_rationale` | string | обязательно | 1-2 предложения — на чём основана оценка |
| `has_notes` | boolean | обязательно | `false`, если по теме нет ни одной заметки — тема выявлена как ожидаемая для домена (по общим знаниям), а не по содержимому vault |
| `note_paths` | string[] | обязательно | заметки домена, отнесённые к теме; `[]`, если `has_notes: false` |
| `related_domain_topics` | string[] | обязательно, всегда `[]` от агента | Всегда пустой массив на выходе `vault-domain-analyzer` — агент анализирует только свой домен и не видит темы других доменов (все домены Фазы 2 запускаются параллельно одним сообщением). Заполняется позже, в Python, на Фазе 3 (`synthesize_taxonomy.py`), сопоставлением тем всех доменов после того как все `{domain_id}-analysis.json` уже записаны |

**Важно**: `topics` обязаны включать не только темы, представленные в имеющихся заметках, но и темы, которые логически ожидаются в этой предметной области, но отсутствуют в vault (`has_notes: false`, `mastery_percent` ≤ 15) — это основа для рекомендаций пользователю закрыть пробелы в знаниях.

**Сохранить в**: `.claude/temp_files/{domain_id}-analysis.json`

## Best Practices

### ✓ Делай

- Анализируй содержимое честно, не гадай
- Обнаруживай зависимости логически
- Пиши JSON с indent 2
- Возвращай сводку ≤4 предложения
- Если файл не читается → статус `"partial"`, пропусти файл

### ✗ Не делай

- Не требуй идеальную точность в mentions/dependencies
- Не выводи полный JSON в ответ
- Не добавляй лишние детали в сводку

## Типы контента

- **overview** — обзор, введение
- **deep-dive** — детальный анализ
- **reference** — справочник, таблицы
- **pattern** — паттерн, best practice
- **example** — пример, use case
- **checklist** — чек-лист, гайд
- **concept** — теоретический материал
- **methodology** — процесс, метод
